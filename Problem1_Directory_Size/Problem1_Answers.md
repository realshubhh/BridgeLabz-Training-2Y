# Problem 1 – Understanding Recursion Mechanics (Directory Size Calculator)

**Code:** `DirectorySize.java` (compile: `javac DirectorySize.java` · run: `java DirectorySize`)

---

## (a) Recursive function design

**Idea:** a file is the simplest possible case; a directory = sum of everything inside it.

- **Base case:** the node is a **file** → return its own size (no more recursive calls)
- **Recursive case:** the node is a **directory** → call the function on every child and add the results
- **Progress toward base case:** each call moves one level *down* the tree, and a tree has finite depth

```
function dirSize(node):
    // BASE CASE
    if node is a file:
        return node.size

    // RECURSIVE CASE
    total = 0
    for each child in node.children:
        total = total + dirSize(child)
    return total
```

## (c) Time complexity

- Let **F** = number of files, **D** = number of directories, **n = F + D** (total nodes)
- Every node is visited **exactly once**:
  - a file does O(1) work (return its size)
  - a directory does O(1) work per child; summed over all directories this is the number of parent→child edges = n − 1
- **Time = O(n) = O(F + D)** – linear in the number of items; it does *not* depend on file sizes
- Example: n = 9 nodes (project, src, docs, guides + 5 files) → 9 calls (see trace: 9 CALL lines)
- **Space = O(h)** where h = height of the tree (call-stack depth). Here h = 4. Worst case (one very deep chain) h = n → O(n)

## (d) Iterative solution

**Yes – it can be solved iteratively.** The recursion's call stack is replaced by an **explicit stack** (or a queue for BFS).

```
function dirSizeIterative(root):
    stack = [root]
    total = 0
    while stack is not empty:
        node = stack.pop()
        if node is a file:
            total += node.size
        else:
            push all children of node onto stack
    return total
```

| Aspect | Recursive | Iterative (explicit stack) |
|--------|-----------|----------------------------|
| Data structure | Implicit call stack | Explicit stack/queue you manage |
| Code | Shorter, mirrors the problem | Slightly longer |
| Time | O(n) | O(n) |
| Space | O(h) call-stack frames | O(n) worst case in stack (all children pushed) – but on the heap |
| Deep trees | Risk of **stack overflow** | No overflow (heap limited only by RAM) |
| Per-directory results (e.g. size of `src`) | Natural (return value of each call) | Harder – needs extra bookkeeping / post-order |
| Readability | Better for tree problems | Better when depth is huge |

**Verdict:** recursion is cleaner here; iteration is safer for extremely deep directory trees (e.g. 100 000 levels).

## (e) Symbolic link creating a cycle

**Problem:** suppose `docs/guides/loop_link → project`. A function that follows links will go
`project → docs → guides → loop_link → project → docs → …` forever.
There is **no base case that is ever reached**, so the call stack grows until **stack overflow (`StackOverflowError` in Java)**
(the code demonstrates this in `naiveFollowLinks`).

**Fix – add extra base cases:**

```
function dirSizeSafe(node, visiting):
    if node is a symlink:            // BASE CASE 1 – do not follow links (like `du`)
        return 0
    if node is a file:               // BASE CASE 2
        return node.size
    if node.id in visiting:          // BASE CASE 3 – already on current path => cycle
        return 0
    visiting.add(node.id)
    total = 0
    for each child in node.children:
        total += dirSizeSafe(child, visiting)
    visiting.remove(node.id)         // backtrack: leave the path
    return total
```

- **Option 1 – skip symlinks:** simplest, matches what `du` does by default
- **Option 2 – follow links but remember visited directories** (using a unique ID such as the inode number or the real path) so each real directory is counted **once**
  - `visiting` (current path only) detects real cycles
  - a global `seen` set additionally avoids double-counting a directory reachable through two links
- Result in the code: both safe versions return **380 KB** even with the loop link present
